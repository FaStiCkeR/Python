# Модели данных

Для описания структуры данных использовались Pydantic-модели.

## Базовая модель TaskBase

```python
class TaskBase(BaseModel):
    title: str = Field(..., min_length=1, max_length=100)
    description: Optional[str] = None
    priority: str = Field(default="medium", pattern="^(low|medium|high)$")
    completed: bool = False
    deadline: Optional[datetime] = None
```

Данная модель содержит основные поля задачи:

| Поле        | Описание          |
|-------------|-------------------|
| title       | Название задачи   |
| description | Описание задачи   |
| priority    | Приоритет задачи  |
| completed   | Статус выполнения |
| deadline    | Срок выполнения   |

---

## Модель TaskCreate

Используется при создании задачи.

```python
class TaskCreate(TaskBase):
    pass
```

---

## Модель TaskUpdate

Используется для полного обновления задачи через PUT-запрос.

```python
class TaskUpdate(BaseModel):
    title: str
    description: str
    priority: str
    deadline: datetime
```

Все поля являются обязательными.

---

## Модель TaskPartialUpdate

Используется для частичного обновления задачи через PATCH-запрос.

```python
class TaskPartialUpdate(BaseModel):
    title: Optional[str]
    description: Optional[str]
    priority: Optional[str]
    deadline: Optional[datetime]
```

Все поля являются необязательными.

---

## Модель TaskInDB

Используется для хранения задачи в памяти приложения.

```python
class TaskInDB(TaskBase):
    id: int
    created_at: datetime
    completed_at: Optional[datetime] = None
```

Дополнительные поля:

| Поле         | Описание                 |
|--------------|--------------------------|
| id           | Уникальный идентификатор |
| created_at   | Дата создания            |
| completed_at | Дата выполнения          |

# Хранение данных

Для хранения данных используются списки Python.

```python
tasks = []
archived_tasks = []
```

Особенности хранения:

* база данных не используется;
* все данные хранятся в оперативной памяти;
* после остановки приложения данные удаляются.

# Генерация идентификаторов

Каждая задача получает уникальный идентификатор.

```python
def _generate_id() -> int:
    global _next_id
    current = _next_id
    _next_id += 1
    return current
```

Используется инкрементный счетчик.

# Реализованные эндпоинты

## GET /

Возвращает информацию о приложении.

Пример ответа:

```json
{
  "message": "Advanced Task API",
  "version": "2.0"
}
```

---

## GET /tasks

Возвращает список задач.

Поддерживаются параметры:

| Параметр  | Назначение             |
|-----------|------------------------|
| completed | Фильтр по статусу      |
| priority  | Фильтр по приоритету   |
| limit     | Ограничение количества |
| sort_by   | Сортировка             |

### Реализованная логика

* фильтрация задач;
* сортировка по дате создания;
* сортировка по приоритету;
* ограничение количества результатов.

---

## GET /tasks/{task_id}

Возвращает задачу по идентификатору.

Если задача отсутствует, возвращается ошибка 404.

---

## POST /tasks

Создает новую задачу.

Дополнительно реализовано:

* автоматическая генерация id;
* автоматическая установка created_at;
* проверка уникальности title.

При попытке создать задачу с существующим названием возвращается ошибка 400.

---

## PUT /tasks/{task_id}

Полностью обновляет задачу.

Особенности:

* все поля обязательны;
* нельзя изменить id;
* нельзя изменить created_at.

---

## PATCH /tasks/{task_id}

Частично обновляет задачу.

Можно изменять:

* title;
* description;
* priority;
* deadline.

---

## PATCH /tasks/{task_id}/complete

Помечает задачу как выполненную.

Дополнительно:

* устанавливается completed = True;
* автоматически добавляется completed_at;
* при повторном выполнении возвращается ошибка.

---

## DELETE /tasks/{task_id}

Удаляет задачу.

Пример ответа:

```json
{
  "message": "Task with id 1 deleted"
}
```

---

## GET /tasks/search

Реализует поиск задач.

Поддерживаемые параметры:

| Параметр  | Назначение                   |
|-----------|------------------------------|
| keyword   | Поиск по title и description |
| priority  | Поиск по приоритету          |
| date_from | Начальная дата               |
| date_to   | Конечная дата                |

---

## GET /tasks/stats

Возвращает статистику.

Статистика включает:

* общее количество задач;
* количество выполненных задач;
* количество невыполненных задач;
* количество просроченных задач;
* распределение задач по приоритетам;
* количество архивированных задач.

---

# Дополнительная бизнес-логика

## Архивация задач

Если количество задач превышает 20, самые старые задачи автоматически перемещаются в архив.

```python
while len(tasks) > 20:
    tasks.sort(key=lambda t: t.created_at)
    oldest = tasks.pop(0)
    archived_tasks.append(oldest)
```

---

## Проверка уникальности title

Реализована проверка уникальности названия задачи.

```python
def _is_title_unique(title: str):
```

Сравнение выполняется без учета регистра.

---

## Просроченные задачи

Задача считается просроченной если:

* deadline меньше текущего времени;
* completed = False.

---

## Сортировка приоритетов

Приоритеты сортируются в следующем порядке:

```text
high → medium → low
```

Для этого используется словарь:

```python
PRIORITY_ORDER = {
    "high": 0,
    "medium": 1,
    "low": 2
}
```
